# COBOL -> Java migration, proven against the real COBOL

A migration is only as good as the proof that the new system behaves like the old one. Everything here is built
around that: the expected output always comes from **running the original COBOL**, never from a model.

```
 COBOL source + copybooks
        |                                 oracle/            real COBOL under GnuCOBOL -> golden output
        v                                 verifier/          field-level diff, record aligned by key
 pipeline/migrate.py  --generate-->  Java (Spring Batch)  --build/run-->  output files
        ^                                        |
        +------- field-level mismatches ---------+   (repair loop, until identical or out of attempts)
```

## Pieces
| Path | What it is |
|---|---|
| `gcp-legacy-env/` | the "before" system: CardDemo's COBOL batch programs on a GCP VM (GnuCOBOL) |
| `oracle/` | runs any scenario through the real COBOL and stores the golden output (`run_oracle.sh`, `make_scenarios.sh`) |
| `oracle/gen_edge_cases.py`, `gen_interest_cases.py` | build targeted scenarios (boundaries, overflow, abends...) from the real initial state |
| `migrated/carddemo-batch/` | reference Java ports of `CBTRN02C` (posting) and `CBACT04C` (interest) + JUnit parity tests |
| `verifier/verify.py` | compares a Java run with the COBOL golden output; JSON report; no LLM involved |
| `verifier/check_all.py` | every program on every scenario |
| `verifier/mutation_check.py` | breaks the Java port in 27 plausible ways; every break must be caught |
| `pipeline/` | the Gemini generate -> verify -> repair loop; results in `pipeline/RESULTS.md` |
| `HANDOVER.md` | conditions, how to replicate on the GCP VM, and what is left |

## Commands
```bash
# 1. capture golden output from the real COBOL (needs GnuCOBOL 3.2 and a CardDemo checkout, see oracle/run_oracle.sh)
oracle/make_scenarios.sh

# 2. verify the reference ports against it
(cd migrated/carddemo-batch && mvn package)          # also runs the JUnit parity tests
python3 verifier/check_all.py
python3 verifier/mutation_check.py                   # takes a few minutes

# 3. let Gemini do the migration, scored by the same verifier
pip install -r pipeline/requirements.txt
export GEMINI_API_KEY=...                            # Google AI Studio key; never committed
python3 pipeline/migrate.py --program posttran --provider gemini --mode guided
python3 pipeline/migrate.py --program posttran --provider gemini --mode naive --max-repairs 0   # single-shot baseline
python3 pipeline/migrate.py --program intcalc  --provider mock     # offline test of the loop (scripted, NOT a model)
```
`--mode guided` adds a generic COBOL-semantics primer; `naive` does not. `--max-repairs 0` is the "just feed it to AI"
baseline. Each run writes `pipeline/runs/<id>/report.json` with, per attempt: build status, scenarios passed, records
matching the COBOL, and prompt/output tokens.

## Things the real COBOL taught us (all reproduced, bug for bug)
- Signed numbers store the sign in the last character; arithmetic truncates instead of rounding and wraps on overflow.
- A transaction that is both over the limit and expired is rejected as *expired* (a later IF overwrites the earlier one).
- Newly created category-balance records inherit the filler of the last record read (hidden working-storage state).
- The interest program never settles the **last account's balance**, although its interest transactions are written.
  The Java port preserves this; `--carddemo.intcalc.fix-last-account=true` applies the evident intent instead.
- A missing account, card cross-reference or default rate row abends the run (rc 16 here) and keeps the work done so far.

## Known gaps
- Reject reason 101 (account missing during posting) is not exercised: it needs a custom initial state.
- `CBSTM03A/B`, `CBEXPORT/CBIMPORT` and the CICS online programs are not runnable under GnuCOBOL and are out of scope.
- The scenarios are generated by rule-based scripts; having Gemini propose additional edge cases (still judged by the real
  COBOL) is a planned extension.
